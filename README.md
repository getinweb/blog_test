## Сознательные ограничения

- **Время разработки.** Общее время на проект до 3 часов.
- **Окружение — dev.** настройки prod выделены архитектурно, но не реализованы. Prod-образы, HTTPS, certbot, secrets и т.д. не реализованы.
- **Без админки и форм загрузки.** Данные добавляются сидингом. Хранилище принимает локальные JPEG, PNG и WebP с ограничением размера через `IMAGE_MAX_BYTES`.
- **Без клиентского JavaScript.** Сортировка и пагинация работают через GET-форму и ссылки. SCSS пересобирается автоматически, страницу браузера нужно обновлять вручную.
- **Просмотры — один раз на статью за PHP-сессию.** HEAD и показ карточек не учитываются. Новая сессия может засчитать просмотр снова; уникальность человека не определяется.
- **Похожие статьи — до трёх.** Приоритет: число общих категорий, дата, ID по убыванию. Текущая статья исключена; при нехватке показываются доступные, при отсутствии блок скрыт.
- **Текст статьи — обычный текст.** HTML экранируется, переносы строк сохраняются. Даты публикации хранятся и выводятся в UTC.
- **Миграции — применение и статус, без отката.** Один SQL-запрос на файл; применённые файлы защищены проверкой SHA-256. После ошибки MySQL DDL схему проверяют вручную.
- **Без `docs/` и отдельной harness-обвязки.** Отложены как избыточные для текущего объёма; документация собрана в README. Локальные `.codex/` и `.claude/` исключены из Git и Docker-контекста.

## Использование ИИ

При разработке использовался ИИ (Codex): для обсуждения архитектуры, планирования и генерации и доработки PHP-кода, тестов, бойлерплейта, SQL, Docker-конфигурации, Makefile, SCSS и Smarty-шаблонов, написания тестов и README, а также для ревью и проверки приложения. Значительная часть кода и тестов сгенерирована ИИ.

Личное участие - 100% заданная архитектура, требования и ограничения, поэтапные проверки и согласования решений, коммиты. Работа велась пошагово: сначала контракты и сигнатуры, затем тесты, затем реализация, затем ревью.

## Архитектура и папки

```text
app/
  assets/scss/     common, layout, categories, articles
  bin/             CLI: настройки, миграции, сидинг
  config/          common/dev/prod/test, bootstrap, фабрики зависимостей
  db/              SQL-миграции и демонстрационные данные
  public/          index.php и публичные ресурсы
  src/
    Article/       Учёт просмотров через PHP-сессии
    Config/        Загрузка и валидация настроек
    Container/     Контейнер внедрения зависимостей
    Controller/    Главная, категория, статья
    Database/      Подключение к MySQL, миграции, сидинг
    Domain/        Сущности статьи и категории, варианты сортировки
    Http/          Запрос, ответ, роутер, обработка ошибок
    Image/         Проверка и хранение изображений
    Repository/    Интерфейсы и PDO-реализации запросов
    View/          Рендеринг через Smarty
  templates/       Страницы и общие карточки
  tests/           Unit, Integration, Functional
  var/             Кеши, сессии, изображения, результаты сборки
docker/            Образы, настройки PHP/nginx/Sass и проверка Docker
compose.yaml       Общие определения сервисов
compose.dev.yaml   Dev-окружение и тестовые сервисы
compose.prod.yaml  Задел для production
Makefile           Команды разработки
```

Единая точка входа через `public/index.php`, HTTP-ядро, роутер и контроллер. SQL и создание сущностей в PDO-репозиториях, HTML — в Smarty-шаблонах. Зависимости явно описаны в `app/config/container.php`; контейнер создаёт экземпляры по запросу.

Таблица `article_category` хранит связи без дублей. Удаление используемой категории запрещено внешним ключом, связи удалённой статьи очищаются каскадно. Списки загружают категории одним дополнительным запросом; главная ограничивает статьи по каждой категории оконной функцией MySQL.

## Работа с проектом

### Требования к окружению

Linux, GNU Make и следующие минимальные версии для проекта:

| Компонент | Версия / требование |
| --- | --- |
| Docker Engine и CLI | **25.0.0+**, запущенный daemon с доступом для текущего пользователя |
| Docker Compose | **2.24.1+**, плагин с командой `docker compose`; старый `docker-compose` v1 не поддерживается |
| Сборщик | BuildKit; не отключать через `DOCKER_BUILDKIT=0` |

Эта базовая связка соответствует [Docker 25.0](https://docs.docker.com/engine/release-notes/25.0/#2500) и покрывает `name` в Compose, `up --wait --wait-timeout` и `ADD --checksum` в Dockerfile Sass. Проверено на Docker Engine/CLI **29.1.3** и Compose **2.40.3**. PHP, Composer, MySQL и Sass работают в контейнерах; Node.js не требуется.

`make doctor` проверяет версии и доступ к Docker; также запускается перед `make build` и `make up`. При ошибках о неподдерживаемых `name`, `--wait-timeout` или `ADD --checksum` проверьте `docker version` и `docker compose version`, обновите Docker и [плагин Compose](https://docs.docker.com/compose/install/linux/). Поле `version:` в YAML совместимость не исправляет: оно [не выбирает версию схемы Compose](https://docs.docker.com/reference/compose-file/version-and-name/).

### Запуск

Из корня проекта:

```sh
make env
make build
make install
make seed
make css-dev
make up
```

Сайт: [http://127.0.0.1:8080](http://127.0.0.1:8080). `make env` сохраняет существующий `.env`. `make seed` запускает MySQL, применяет миграции и заполняет только пустую БД; для запуска без демо-данных замените его на `make migrate`.

### Настройки

Основные параметры в `.env`: `HTTP_PORT=8080`, `APP_ENV=dev`, `ARTICLES_PER_PAGE=12`, `IMAGE_MAX_BYTES=5242880` (5 МиБ). Остальные переменные перечислены в [.env.example](.env.example). Пароли из примера предназначены для dev; их изменение не меняет пароли уже созданной БД.

Compose передаёт настройки в процесс PHP. Приоритет в приложении: `config/common` → `config/<окружение>` → переменные процесса. После изменения `.env` выполните `make up`; `make restart` новое окружение не применяет. UID/GID на Linux берутся из текущего пользователя; при необходимости задаются через `make build LOCAL_UID=1000 LOCAL_GID=1000`.

### Основные команды

| Команда | Назначение |
| --- | --- |
| `make doctor` | Проверить версии Docker/Compose и доступ к daemon |
| `make up` / `make down` | Запустить / остановить окружение; dev-БД сохраняется |
| `make check` | Настройки, SCSS, Composer, PHP-синтаксис, стиль, PHPStan и все тесты |
| `make cs-fix` | Исправить стиль PHP |
| `make test` | Все тесты; отдельно: `make test-unit`, `make test-integration`, `make test-functional` |
| `make migrate` / `make migrate-status` | Применить миграции / показать статус |
| `make seed` | Заполнить пустую dev-БД |
| `make css-dev` / `make css-watch` | Собрать dev-CSS / включить наблюдение (также запускается через `make up`) |
| `make css-build` | Минифицированный CSS без source maps в `app/var/build/assets/css/` |
| `make ps` / `make logs` / `make shell` | Состояние сервисов / логи / shell PHP-контейнера |
| `make help` | Полный список команд |

Тесты работают с отдельной БД `blog_test` в tmpfs и изолированной Docker-сети. Они меняют тестовые таблицы, поэтому наборы тестов в одном Compose-проекте запускаются последовательно. Dev-CSS находится в `app/public/assets/css/`; сборка `css-build` его не заменяет.

### Проверка страниц

Адреса: `/`, `/category?id=1`, `/category?id=1&sort=views&page=2`, `/article?id=1`. По умолчанию `sort=date` — новые статьи первыми; `sort=views` — наиболее просматриваемые. При равенстве учитываются дата и ID по убыванию. Смена сортировки возвращает на первую страницу.

Некорректный `id`, а у категории также `page` или `sort`, возвращает 400; отсутствующие записи и страницы — 404; неподдерживаемые методы существующих маршрутов — 405. Пустая категория на первой странице возвращает 200. HEAD не содержит тела и не увеличивает просмотры.

### Обновление зависимостей

Образы зафиксированы digest, Debian — снимком на `2026-10-04`, Dart Sass 1.105.1 — SHA-256 архивов, PHP-пакеты — `app/composer.lock`. Обычная установка: `make install`. Для обновления образов измените `PINNED_IMAGES` в Makefile, выполните `make pin-images` и перенесите ссылки в Dockerfile и Compose. Версию Sass и контрольные суммы меняйте вместе в `docker/sass/Dockerfile`.
